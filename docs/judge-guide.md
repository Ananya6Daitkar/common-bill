# Try Common Bill in three minutes

Open the public app. No sign-in, workspace token, or personal API key is needed for the fixed live demo.

1. Choose **Try the live demo**. It evaluates two films and two books with real Qloo and Groq calls. Operational details are fictional and marked as such. An original API timestamp remains visible if a result is reused.
2. Review the selected bill, budget, runtime and stock. Open **Inspect the evidence** to examine query receipts and the decision trace. Film-to-book and book-to-film affinities are separate; they are not audience overlap percentages.
3. Record **Cinema reviewed** and **Bookshop reviewed**. These are local review notes, not authenticated approvals.
4. Choose **Bookseller unavailable**. Check the new host, supplied costs and revision differences. Reviews reset.
5. Choose **This pairing doesn’t work. Revise it.** The fixed public scenario excludes that pair because the partners have already programmed it.
6. Choose **Budget drops to £100**. The system stops with practical blockers rather than making up a feasible event.
7. Choose **Reset live scenario**, then **The evidence test → Run a blind comparison**. Both arms use the same model and input fingerprint. State a preference or no preference, then reveal the methods. One run is not a benchmark or impact study.
8. From the planning desk, **Export event brief** provides a readable preview and copy/download options. Evidence and comparison exports are JSON.

## If a service is busy
A new run may take up to a few minutes when provider limits require a bounded wait. A rate-limit message is an actual upstream limit, not a fabricated fallback. Retry after a minute. Rehearsal remains available without vendor calls, but is clearly labeled as feasibility-only.

## Own workspace
Outside the fixed demo, briefs and catalogs are editable and persist on the device. Arbitrary live vendor calls require a server-configured workspace token; the public fixed demo does not. Real organizers must verify rights, availability, costs, runtime and stock before using their own catalog in live mode.

## What this demonstrates—and does not
It demonstrates a working cultural-evidence workflow, hard-constraint enforcement, revisions, and inspectable decisions. It does not demonstrate attendance uplift, revenue, real user adoption, or private multi-user collaboration.
